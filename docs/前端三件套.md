# 前端三件套核心笔记

## 1. HTML

**HTML 概述**：HTML（HyperText Markup Language，超文本标记语言）用于描述网页内容结构，是浏览器解析页面的基础骨架。HTML 通过标签表达文本、图片、链接、表单、媒体、脚本等内容的语义关系，决定页面中“有什么内容”以及内容之间的层级结构。

HTML 不负责复杂样式与交互逻辑，通常与 CSS、JavaScript 协同工作：

| 技术 | 核心职责 |
| --- | --- |
| HTML | 定义页面结构与内容语义 |
| CSS | 控制视觉样式与布局表现 |
| JavaScript | 实现动态交互与业务逻辑 |

### 1.1 HTML 5

**HTML5 新特性**：

| 新特性/标签 | 核心作用/应用场景 |
| --- | --- |
| `header`、`nav`、`main`、`section`、`article`、`aside`、`footer` | 提供语义化页面结构，提升可读性、可维护性与搜索引擎理解能力 |
| `audio`、`video` | 原生支持音频与视频播放，减少对 Flash 等第三方插件的依赖 |
| `canvas` | 提供基于 JavaScript 的位图绘图能力，适用于图表、游戏、图像处理等场景 |
| `svg` | 提供矢量图形描述能力，适用于图标、可缩放插画、数据可视化等场景 |
| 表单输入类型：`email`、`url`、`number`、`date`、`range`、`color` | 增强表单语义与浏览器原生校验能力，优化移动端输入体验 |
| 表单属性：`required`、`placeholder`、`pattern`、`autocomplete` | 减少基础表单校验与提示逻辑的 JavaScript 编写成本 |
| `localStorage`、`sessionStorage` | 提供浏览器本地键值存储能力，适合保存轻量级状态、配置与临时数据 |
| Web Worker | 将耗时计算迁移到后台线程，避免阻塞主线程渲染与交互 |
| Geolocation API | 获取用户地理位置信息，常用于地图、附近服务、位置推荐等场景 |
| Drag and Drop API | 提供原生拖拽交互能力，适用于文件上传、看板排序、拖拽编辑器等场景 |

**audio 与 video**：

`audio` 与 `video` 是 HTML5 提供的原生媒体标签，用于在页面中直接嵌入音频与视频资源。浏览器会根据资源格式、编解码能力与标签属性执行加载、播放、暂停、进度控制等行为。

```html
<audio controls src="/assets/audio/demo.mp3">
  当前浏览器不支持 audio 标签。
</audio>

<video controls width="640" poster="/assets/images/poster.jpg">
  <source src="/assets/video/demo.mp4" type="video/mp4" />
  <source src="/assets/video/demo.webm" type="video/webm" />
  当前浏览器不支持 video 标签。
</video>
```

常用属性如下：

| 属性 | 适用标签 | 作用 |
| --- | --- | --- |
| `src` | `audio`、`video` | 指定媒体资源地址 |
| `controls` | `audio`、`video` | 显示浏览器原生播放控制条 |
| `autoplay` | `audio`、`video` | 页面加载后尝试自动播放；现代浏览器通常限制非静音自动播放 |
| `muted` | `audio`、`video` | 静音播放，常与 `autoplay` 配合用于视频自动播放 |
| `loop` | `audio`、`video` | 媒体播放结束后自动重新播放 |
| `preload` | `audio`、`video` | 控制预加载策略，常见值包括 `none`、`metadata`、`auto` |
| `poster` | `video` | 指定视频加载或播放前展示的封面图 |
| `width`、`height` | `video` | 设置视频显示区域尺寸 |

常用事件如下：

| 事件 | 触发时机 | 典型用途 |
| --- | --- | --- |
| `loadedmetadata` | 元数据加载完成 | 获取时长、尺寸等基础信息 |
| `canplay` | 浏览器已具备开始播放的能力 | 切换加载状态、启用播放按钮 |
| `play` | 播放开始 | 记录播放状态、埋点统计 |
| `pause` | 播放暂停 | 同步 UI 状态、保存播放进度 |
| `timeupdate` | 播放进度变化 | 更新进度条、显示当前播放时间 |
| `ended` | 播放结束 | 触发下一集、重置 UI、上报完成事件 |
| `error` | 加载或播放失败 | 展示错误提示、切换备用资源 |

```js
const video = document.querySelector("video");

video.addEventListener("timeupdate", () => {
  const progress = video.currentTime / video.duration;
  console.log(`播放进度：${Math.round(progress * 100)}%`);
});

video.addEventListener("ended", () => {
  console.log("视频播放结束");
});
```

**svg**：

SVG（Scalable Vector Graphics，可缩放矢量图形）使用 XML 描述图形结构，本质是基于路径、形状、文本、滤镜等元素的矢量图。与位图不同，SVG 在缩放时不会因像素拉伸而失真，适合构建图标、品牌标识、流程图、地图、数据可视化图形等界面资产。

SVG 在前端中的核心优势包括：

| 优势 | 说明 |
| --- | --- |
| 无损缩放 | 在不同分辨率与设备像素比下保持清晰 |
| 可被 CSS 控制 | 可通过 `fill`、`stroke`、`width`、`height` 等属性调整样式 |
| 可被 JavaScript 操作 | SVG 元素存在于 DOM 中，可绑定事件并动态修改 |
| 体积可控 | 简单图标通常比等效位图更小，适合图标系统 |
| 语义与可访问性更强 | 可添加 `title`、`role`、`aria-label` 等辅助信息 |

```html
<svg width="32" height="32" viewBox="0 0 32 32" role="img" aria-label="成功">
  <circle cx="16" cy="16" r="14" fill="#16a34a" />
  <path d="M9 16.5l4.2 4.2L23 11" fill="none" stroke="#fff" stroke-width="3" />
</svg>
```

## 2. CSS

**CSS 概述**：CSS（Cascading Style Sheets，层叠样式表）用于描述 HTML 元素的视觉表现与布局方式。浏览器通过选择器匹配元素，再根据层叠规则、继承规则、优先级、盒模型、布局模型等机制计算最终样式。

CSS 的核心机制包括：

| 机制 | 作用 |
| --- | --- |
| 选择器 | 匹配需要应用样式的 HTML 元素 |
| 层叠与优先级 | 决定多个样式规则冲突时的最终生效规则 |
| 继承 | 允许部分样式从父元素传递到子元素 |
| 盒模型 | 描述元素由 `content`、`padding`、`border`、`margin` 构成的空间结构 |
| 布局模型 | 通过普通流、Flexbox、Grid、定位、浮动等方式组织页面布局 |
| 响应式能力 | 使用媒体查询、弹性单位、容器查询等适配不同设备与视口 |

### 2.1 Tailwind CSS

**核心理念**：Tailwind CSS 采用 Utility-First（原子化 CSS）设计思想。该思想将常见样式拆分为大量低粒度工具类，例如 `flex`、`items-center`、`p-4`、`text-sm`、`bg-blue-600`。开发时直接在 HTML 或组件模板中组合这些工具类，从而完成样式声明。

Utility-First 的关键特征如下：

| 特征 | 说明 |
| --- | --- |
| 样式原子化 | 每个类通常只表达一个样式规则或一组极小规则 |
| 组合式构建 | 通过组合多个工具类构建具体组件样式 |
| 约束式设计 | 颜色、间距、字号、断点等来自统一配置，减少随意值 |
| 低命名成本 | 减少为样式块创建语义化 class 名称的成本 |
| 构建期优化 | 未使用的工具类可在构建阶段被裁剪，降低产物体积 |

**优缺点分析**：

| 对比维度 | Tailwind CSS | 传统语义化 CSS / BEM |
| --- | --- | --- |
| 样式组织方式 | 样式直接组合在模板或组件结构中 | 样式集中在 CSS 文件中，通过语义化类名关联 |
| 命名成本 | 基本不需要为局部样式命名 | 需要维护 block、element、modifier 等命名规则 |
| 复用方式 | 复用工具类、设计令牌与组件封装 | 复用语义 class、mixin、变量与组件样式 |
| 可读性 | 熟悉工具类后可快速理解样式细节，但 class 列表可能较长 | HTML 更简洁，但需要在 HTML 与 CSS 之间跳转理解样式 |
| 一致性 | 默认受配置约束，间距、颜色、字号更容易统一 | 依赖团队规范与变量体系，随意值更容易扩散 |
| 动态样式 | 与组件状态、条件 class 结合紧密 | 通常通过状态类或额外 class 切换 |
| 长期维护 | 适合组件化工程，推荐结合组件抽象控制重复 class | 适合样式语义边界清晰、设计系统成熟的项目 |
| 主要风险 | 模板中 class 过长、动态拼接导致构建裁剪失效 | 命名膨胀、选择器耦合、样式覆盖链条复杂 |

两种方案并非绝对互斥。工程中常见的实践是：使用 Tailwind 处理大部分局部样式，使用组件封装沉淀可复用 UI，再对少量复杂样式或第三方内容区域保留独立 CSS。

**基础实践**：

以下示例使用 Tailwind CSS 构建一个常见按钮组件。按钮样式由布局、间距、颜色、圆角、阴影、过渡、交互状态等工具类组合而成。

```html
<button
  type="button"
  class="inline-flex items-center justify-center rounded-md bg-blue-600 px-4 py-2 text-sm font-medium text-white shadow-sm transition hover:bg-blue-700 focus:outline-none focus:ring-2 focus:ring-blue-500 focus:ring-offset-2 disabled:cursor-not-allowed disabled:bg-slate-300"
>
  保存配置
</button>
```

在组件化框架中，常将重复出现的工具类封装到组件内部，由外部传入状态与事件：

```jsx
function PrimaryButton({ disabled, children, onClick }) {
  return (
    <button
      type="button"
      disabled={disabled}
      onClick={onClick}
      className="inline-flex items-center justify-center rounded-md bg-blue-600 px-4 py-2 text-sm font-medium text-white shadow-sm transition hover:bg-blue-700 focus:outline-none focus:ring-2 focus:ring-blue-500 focus:ring-offset-2 disabled:cursor-not-allowed disabled:bg-slate-300"
    >
      {children}
    </button>
  );
}
```

## 3. JavaScript

**JavaScript 概述**：JavaScript 是浏览器中的主要脚本语言，负责页面交互、状态管理、DOM 操作、网络请求、数据处理与运行时逻辑控制。现代前端工程中，JavaScript 也承担组件渲染、路由管理、构建工具配置、服务端渲染、跨端开发等职责。

JavaScript 的核心地位来自三个方面：

| 维度 | 说明 |
| --- | --- |
| 浏览器原生支持 | 主流浏览器内置 JavaScript 引擎，可直接执行脚本 |
| DOM 与 Web API 访问能力 | 可操作页面结构、监听事件、发起网络请求、使用存储与媒体能力 |
| 生态规模 | 与 Node.js、npm、前端框架、构建工具、测试工具形成完整工程体系 |

### 3.1 JS 语言基础

**核心概念梳理**：

JavaScript 数据类型分为原始类型与引用类型。原始类型的值通常按值访问，引用类型的变量保存对象引用。

| 类型分类 | 具体类型 | 特点 |
| --- | --- | --- |
| 原始类型 | `string`、`number`、`boolean`、`undefined`、`null`、`symbol`、`bigint` | 值本身不可变，比较时通常比较值 |
| 引用类型 | `object`、`array`、`function`、`date`、`regexp` 等 | 变量保存引用地址，比较时通常比较引用 |

变量声明方式包括 `var`、`let`、`const`。现代代码中通常优先使用 `const`，需要重新赋值时使用 `let`，避免使用 `var`。

| 声明方式 | 作用域 | 是否提升 | 是否可重复声明 | 是否可重新赋值 | 典型用途 |
| --- | --- | --- | --- | --- | --- |
| `var` | 函数作用域 | 会提升并初始化为 `undefined` | 可以 | 可以 | 旧代码兼容，现代代码不推荐 |
| `let` | 块级作用域 | 会提升，但存在暂时性死区 | 不可以 | 可以 | 需要重新赋值的局部变量 |
| `const` | 块级作用域 | 会提升，但存在暂时性死区 | 不可以 | 不可以重新绑定 | 常量引用、函数、对象、数组 |

作用域用于决定变量的可访问范围。JavaScript 常见作用域包括全局作用域、函数作用域、块级作用域与模块作用域。

闭包是函数与其词法作用域环境的组合。当内部函数在外部函数执行结束后仍然持有外部变量引用时，就形成闭包。闭包常用于数据封装、函数工厂、缓存、事件回调等场景。

```js
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
```

闭包可以保留局部状态，但长期持有不再需要的对象引用可能增加内存占用。因此在事件监听、定时器、缓存结构中需要关注引用释放。

### 3.2 ES6 和 ES Next

**现代 JS 语法速览**：

| 特性名称 | 语法示例 | 解决的核心痛点 |
| --- | --- | --- |
| 箭头函数 | `const add = (a, b) => a + b;` | 简化函数表达式语法，并固定词法 `this` |
| 解构赋值 | `const { id, name } = user;` | 简化对象与数组取值逻辑，减少重复访问路径 |
| 模板字符串 | ``const msg = `Hello, ${name}`;`` | 简化字符串拼接，支持多行字符串与表达式插值 |
| Promise | `fetch(url).then(res => res.json());` | 统一异步结果抽象，缓解回调嵌套与错误传递混乱 |
| `let` / `const` | `const list = []; let index = 0;` | 引入块级作用域，减少 `var` 带来的变量泄漏与提升问题 |
| 默认参数 | `function request(url, method = "GET") {}` | 减少函数参数兜底逻辑 |
| 剩余参数 | `function sum(...nums) {}` | 以数组形式收集不定数量参数 |
| 展开语法 | `const next = [...items, newItem];` | 简化数组、对象复制与参数展开 |
| 模块化 | `import { ref } from "vue";` | 提供语言层面的模块导入导出能力 |
| 类语法 | `class UserService {}` | 提供更接近传统面向对象语言的构造器与继承语法 |
| 可选链 | `const city = user.profile?.address?.city;` | 安全访问深层属性，减少空值判断样板代码 |
| 空值合并 | `const size = inputSize ?? 16;` | 仅在 `null` 或 `undefined` 时使用默认值，避免误判 `0`、`false`、空字符串 |

ES Next 通常指已经进入标准流程或已被主流运行时逐步支持的新语法与新 API。工程中使用 ES Next 特性时，需要结合目标浏览器、Node.js 版本、构建工具转译能力与 polyfill 策略综合判断。

### 3.3 异步编程

**演进历程**：

JavaScript 运行环境通常采用事件循环处理异步任务。异步编程模型的演进重点在于降低嵌套复杂度、统一错误处理、提升代码可读性，并更好地表达异步流程之间的依赖关系。

| 阶段 | 基本形式 | 解决的问题 | 主要局限 |
| --- | --- | --- | --- |
| Callback | `readFile(path, (err, data) => {})` | 以函数回调接收异步结果，是早期异步 API 的基础模式 | 多层嵌套容易形成回调地狱，错误处理分散，流程控制困难 |
| Promise | `request().then(handle).catch(handleError)` | 将异步结果抽象为状态机，统一成功、失败与链式调用 | 链式调用仍可能较长，复杂条件流程可读性有限 |
| Async/Await | `const data = await request();` | 使用接近同步代码的形式描述异步流程，提升顺序依赖逻辑的可读性 | 本质仍基于 Promise，需要理解并发控制、错误捕获与阻塞边界 |

回调函数阶段通过约定回调参数传递异步结果。Node.js 早期大量 API 采用 Error First Callback，即第一个参数表示错误，后续参数表示结果。

```js
readFile("config.json", (error, data) => {
  if (error) {
    handleError(error);
    return;
  }

  parseConfig(data, (parseError, config) => {
    if (parseError) {
      handleError(parseError);
      return;
    }

    startApp(config);
  });
});
```

Promise 将异步操作封装为 `pending`、`fulfilled`、`rejected` 三种状态，并通过 `then`、`catch`、`finally` 组合后续流程。

```js
fetch("/api/user")
  .then((response) => response.json())
  .then((user) => renderUser(user))
  .catch((error) => reportError(error))
  .finally(() => hideLoading());
```

Async/Await 是 Promise 之上的语法糖，使异步代码可以使用 `try...catch` 进行集中错误处理。

```js
async function loadUser() {
  try {
    showLoading();

    const response = await fetch("/api/user");
    const user = await response.json();

    renderUser(user);
  } catch (error) {
    reportError(error);
  } finally {
    hideLoading();
  }
}
```

需要并发执行多个互不依赖的异步任务时，直接顺序 `await` 会增加总耗时。此类场景通常使用 `Promise.all`、`Promise.allSettled`、`Promise.race` 等组合 API。

```js
const [user, permissions] = await Promise.all([
  fetch("/api/user").then((response) => response.json()),
  fetch("/api/permissions").then((response) => response.json()),
]);
```

## 4. Node.js 生态与进阶

### 4.1 Node.js 基础

**运行环境本质**：Node.js 是基于 Chrome V8 引擎构建的 JavaScript 运行时，使 JavaScript 可以脱离浏览器在服务器、命令行工具、构建系统、桌面应用后端等环境中执行。

Node.js 的核心特性包括：

| 特性 | 说明 |
| --- | --- |
| V8 引擎 | 负责解析、编译与执行 JavaScript，提供高性能 JIT 编译能力 |
| 事件驱动 | 通过事件循环调度异步任务，适合处理大量 I/O 事件 |
| 非阻塞 I/O | 文件、网络、数据库等 I/O 操作通常不会阻塞主线程 |
| 单线程主模型 | JavaScript 代码主要在单个事件循环线程中执行，降低共享状态并发复杂度 |
| libuv | 提供跨平台异步 I/O、线程池、事件循环等底层能力 |
| npm 生态 | 提供庞大的包管理与模块复用体系 |

Node.js 适合 I/O 密集型服务，例如 API 服务、BFF 层、实时通信、构建工具、CLI 工具等。CPU 密集型任务需要结合 Worker Threads、子进程、任务队列或独立计算服务进行拆分。

### 4.2 进阶框架和库

**Sequelize**：Sequelize 是 Node.js 生态中的 ORM（Object Relational Mapping，对象关系映射）框架，用于在 JavaScript 对象模型与关系型数据库表结构之间建立映射关系。它支持 MySQL、PostgreSQL、SQLite、MariaDB、Microsoft SQL Server 等数据库。

Sequelize 的核心机制包括：

| 机制 | 说明 |
| --- | --- |
| Model | 使用 JavaScript 类或定义对象描述数据库表结构 |
| DataTypes | 描述字段类型、是否允许为空、默认值、校验规则等 |
| Association | 描述表之间的一对一、一对多、多对多关系 |
| Migration | 管理数据库结构变更，便于团队协作与版本追踪 |
| Query Builder | 通过对象配置生成 SQL，减少手写 SQL 的重复工作 |
| Transaction | 支持事务控制，保证多步骤数据库操作的一致性 |

```js
import { DataTypes } from "sequelize";
import { sequelize } from "./database.js";

const User = sequelize.define("User", {
  id: {
    type: DataTypes.INTEGER,
    primaryKey: true,
    autoIncrement: true,
  },
  name: {
    type: DataTypes.STRING,
    allowNull: false,
  },
  email: {
    type: DataTypes.STRING,
    allowNull: false,
    unique: true,
  },
});

const users = await User.findAll({
  where: {
    name: "Felix",
  },
});
```

ORM 可以提升 CRUD 开发效率与类型抽象能力，但复杂查询、性能调优、索引策略、事务边界仍需要理解底层 SQL 与数据库执行计划。

**Axios**：Axios 是基于 Promise 的 HTTP 客户端，可同时运行在浏览器与 Node.js 环境中。它封装了请求配置、响应处理、错误处理、拦截器、取消请求、超时控制等常用能力。

Axios 的核心优势包括：

| 能力 | 说明 |
| --- | --- |
| 请求与响应拦截器 | 可统一注入 Token、处理错误码、刷新登录态、记录日志 |
| 自动 JSON 转换 | 默认对 JSON 请求与响应进行序列化和反序列化处理 |
| 超时配置 | 可通过 `timeout` 控制请求最大等待时间 |
| 统一错误对象 | 对 HTTP 错误、网络错误、配置错误进行统一封装 |
| 实例化配置 | 可创建多个 HTTP 实例，隔离不同服务的 baseURL、headers、拦截器 |
| 浏览器与 Node.js 双端支持 | 浏览器使用 XHR 或 Fetch 适配，Node.js 使用 HTTP 相关能力 |

Axios 与原生 Fetch API 对比如下：

| 对比维度 | Axios | Fetch API |
| --- | --- | --- |
| API 来源 | 第三方库 | 浏览器原生 Web API |
| Promise 支持 | 原生基于 Promise | 原生基于 Promise |
| JSON 处理 | 默认自动转换 JSON 数据 | 需要显式调用 `response.json()` |
| HTTP 错误处理 | 非 2xx 状态通常进入 rejected 流程 | 非 2xx 状态不会自动 reject，需要检查 `response.ok` |
| 拦截器 | 内置请求与响应拦截器 | 原生不提供，需要自行封装 |
| 超时控制 | 内置 `timeout` 配置 | 通常结合 `AbortController` 实现 |
| 包体积 | 增加额外依赖 | 无额外依赖 |

```js
import axios from "axios";

const http = axios.create({
  baseURL: "/api",
  timeout: 8000,
});

http.interceptors.request.use((config) => {
  config.headers.Authorization = `Bearer ${getToken()}`;
  return config;
});

http.interceptors.response.use(
  (response) => response.data,
  (error) => Promise.reject(normalizeHttpError(error)),
);

const user = await http.get("/user");
```

**Mock.js**：Mock.js 是用于生成模拟数据与拦截 Ajax 请求的前端开发工具。它通过数据模板语法生成随机数据，并可在开发阶段拦截指定 URL 与请求方法，使前端在后端接口未完成或接口不稳定时独立推进页面开发。

Mock.js 的典型作用包括：

| 场景 | 说明 |
| --- | --- |
| 接口未完成 | 使用模拟接口返回结构化数据，前端页面可提前联调 UI 与状态 |
| 批量造数 | 使用模板快速生成列表、用户、订单、图表等测试数据 |
| 边界测试 | 模拟空列表、异常状态、超长文本、分页结果等情况 |
| 解耦开发 | 降低前后端开发进度互相阻塞的风险 |

```js
import Mock from "mockjs";

Mock.mock("/api/users", "get", {
  code: 0,
  message: "ok",
  "data|5-10": [
    {
      "id|+1": 1,
      name: "@cname",
      email: "@email",
      createdAt: "@datetime",
    },
  ],
});
```

生产环境通常不应引入 Mock 拦截逻辑。工程中可通过环境变量、构建模式或开发服务器代理配置区分真实接口与模拟接口。

### 4.3 JS 开发 Harmony 实践

**跨端生态简述**：在鸿蒙（HarmonyOS）生态中，JavaScript 及其相关技术栈可用于应用界面开发、轻量级服务逻辑、跨端业务复用与 IoT 设备交互。随着 ArkUI、TypeScript、声明式 UI 范式与多设备协同能力的发展，前端开发经验在鸿蒙应用开发中具有一定迁移价值。

JavaScript 在 HarmonyOS 或泛物联网设备开发中的价值主要体现在：

| 方向 | 说明 |
| --- | --- |
| 声明式 UI 迁移 | 前端组件化、状态驱动 UI 的经验可迁移到声明式应用开发模型 |
| 多端业务复用 | 表单校验、数据转换、状态管理、网络请求等逻辑可沉淀为跨端模块 |

## 5. 跨平台与移动端适配

### 5.1 跨平台与多端开发：Taro

**Taro 框架机制**：Taro 是面向多端应用开发的跨平台框架，核心目标是实现“一次编写，多端运行”。开发者使用 React 风格或类 React 的组件化语法编写业务代码，Taro 在编译阶段将代码转换为不同目标平台可识别的产物。

Taro 的核心工作机制如下：

| 机制 | 说明 |
| --- | --- |
| 编译时转换 | 将统一代码转换为微信小程序、H5、React Native 等目标平台代码 |
| 运行时适配 | 对组件、API、事件、生命周期等差异进行封装与抹平 |
| 统一组件模型 | 提供跨端组件抽象，使业务代码尽量保持一致 |
| 条件编译 | 针对平台差异编写特定代码，处理无法完全统一的能力 |
| 工程化集成 | 提供脚手架、编译、预览、打包、插件等完整开发流程 |

Taro 在多端适配中的作用如下：

| 目标端 | 适配价值 |
| --- | --- |
| 微信小程序 | 将组件与页面编译为小程序原生结构，复用主流前端开发模式 |
| H5 | 输出 Web 页面，适配浏览器运行环境 |
| React Native | 复用部分业务逻辑与组件结构，接入原生移动端能力 |
| 其他小程序平台 | 通过平台适配层支持支付宝、百度、字节跳动等小程序生态 |

跨端框架无法完全消除平台差异。支付、登录、分享、地图、蓝牙、文件系统、推送等能力通常具有明显平台边界，需要通过条件编译、平台 API 封装或插件能力处理。

```jsx
import { View, Text } from "@tarojs/components";
import Taro from "@tarojs/taro";

export default function ProfileCard() {
  const handleClick = () => {
    Taro.showToast({
      title: "已打开资料",
      icon: "success",
    });
  };

  return (
    <View className="profile-card" onClick={handleClick}>
      <Text className="profile-card__title">用户资料</Text>
    </View>
  );
}
```

### 5.2 移动端适配

**UserAgent**：UserAgent（UA）是浏览器或客户端在 HTTP 请求头中携带的字符串，用于标识当前运行环境的浏览器、操作系统、设备类型、渲染引擎等信息。前端可通过 `navigator.userAgent` 读取 UA 字符串，并根据规则识别移动端、系统版本、浏览器类型或内嵌 WebView 环境。

UA 字符串通常包含以下信息：

| 信息类别 | 示例 | 说明 |
| --- | --- | --- |
| 浏览器标识 | `Chrome/124.0.0.0`、`Safari/605.1.15` | 表示浏览器名称与版本 |
| 渲染引擎 | `AppleWebKit/537.36`、`Gecko` | 表示页面渲染相关引擎信息 |
| 操作系统 | `Windows NT 10.0`、`Android 14`、`iPhone OS 17_4` | 表示系统类型与版本 |
| 设备信息 | `Mobile`、`iPhone`、`iPad` | 用于辅助判断设备类型 |
| 宿主环境 | `MicroMessenger`、`AlipayClient` | 常用于识别微信、支付宝等内嵌浏览器 |

```js
const ua = navigator.userAgent;

const isIOS = /iPhone|iPad|iPod/i.test(ua);
const isAndroid = /Android/i.test(ua);
const isWechat = /MicroMessenger/i.test(ua);
```

UA 识别适合处理平台差异、兼容性兜底、特定宿主能力判断等场景，但不适合替代响应式布局。由于 UA 可能被伪造，且浏览器厂商逐步减少 UA 中的高精度信息，能力检测通常比 UA 判断更稳健。

```js
const supportsTouch = "ontouchstart" in window || navigator.maxTouchPoints > 0;
const supportsClipboard = Boolean(navigator.clipboard?.writeText);
```

**Viewport**：`viewport` 元标签用于控制移动浏览器中布局视口的尺寸与缩放行为，是移动端响应式布局的基础配置。未正确设置 viewport 时，移动浏览器可能使用较宽的默认布局视口，导致页面被整体缩小后显示。

常见配置如下：

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

关键属性如下：

| 属性 | 常用值 | 作用 |
| --- | --- | --- |
| `width` | `device-width` | 将布局视口宽度设置为设备 CSS 像素宽度 |
| `initial-scale` | `1.0` | 设置页面初始缩放比例 |
| `minimum-scale` | `1.0` | 设置用户可缩小的最小比例 |
| `maximum-scale` | `1.0` | 设置用户可放大的最大比例 |
| `user-scalable` | `yes` / `no` | 控制用户是否可以手动缩放页面 |
| `viewport-fit` | `cover` | 允许页面扩展到刘海屏、安全区域之外，常配合 `env(safe-area-inset-*)` 使用 |

移动端适配中，`viewport` 通常与响应式单位、媒体查询、Flexbox、Grid、图片自适应、安全区域适配等方案配合使用。

```css
.page {
  min-height: 100vh;
  padding: 16px;
  padding-bottom: calc(16px + env(safe-area-inset-bottom));
}

.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(160px, 1fr));
  gap: 12px;
}

img {
  max-width: 100%;
  height: auto;
}
```

在可访问性要求较高的页面中，不建议禁用用户缩放。`maximum-scale=1.0` 与 `user-scalable=no` 可能影响低视力用户放大阅读内容，应谨慎使用。
